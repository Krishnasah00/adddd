Practical patterns for future modules. Every example calls the real toast API; run it here or copy it. Delays are simulated, there is no backend.

AJAX Operations

Loading, then success (simulated delay)
const id = toast.loading("Saving changes...");

setTimeout(() => {
  toast.update(id, { type: "success", title: "Saved", message: "Changes saved successfully." });
}, 1500);
Loading, then error (simulated delay)
const id = toast.loading("Saving changes...");

setTimeout(() => {
  toast.update(id, { type: "error", title: "Save failed", message: "The server could not save your changes." });
}, 1500);
toast.promise helper (simulated)
toast.promise(
  new Promise(resolve => setTimeout(() => resolve({ name: "Alex" }), 1500)),
  { loading: "Saving...", success: user => `Saved ${user.name}`, error: "Unable to save." }
);

Real requests (copy only)

fetch + loading toast
const id = toast.loading("Saving...");

fetch("/your-endpoint", { method: "POST", body: new FormData(form) })
  .then(res => res.ok ? res.json() : Promise.reject(res))
  .then(data => toast.update(id, { type: "success", message: data.message || "Saved." }))
  .catch(() => toast.update(id, { type: "error", message: "Request failed." }));
jQuery $.ajax
const id = toast.loading("Saving...");

$.ajax({ url: form.action, method: "POST", data: $(form).serialize() })
  .done(res => toast.update(id, { type: "success", message: res.message }))
  .fail(xhr => toast.update(id, { type: "error", message: (xhr.responseJSON && xhr.responseJSON.message) || "Request failed." }));
