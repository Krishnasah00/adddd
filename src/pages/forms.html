Forms

Reusable form elements and validation.

Component overview

Reusable form fields, layout helpers and client-side validation.

Original functionality (from the archive)

  • Field shell: label, help text, error message, required marker, ARIA wiring
  • Input, password (show/hide), number stepper, phone, currency, percentage, textarea, select, multi-select, combobox, checkbox, radio group, switch, segmented control
  • File and image upload (drag and drop), OTP, tag input, colour picker, repeater
  • Form sections, rows and action bars; validation messages

Dashboard adaptations / additions

  • The original is React + react-hook-form; this port uses native constraints, data-rule rules and data-ff widgets
  • Sizes (sm/md/lg), variants (filled/underline), density-aware height enhancement
  • Laravel 422 error mapping and appform:* events enhancement
  • Native date input in place of a missing date picker enhancement

Known limitations

  • Widgets are enhanced from markup, not generated from a schema
  • Server-side Laravel rendering of fields is left to your Blade partials

        Forms Usage Examples

        Create a form
        <form id="signup" data-ff-form novalidate>
  <div class="ff-field" data-required>
    <label class="ff-label" for="email">Email <span class="ff-req">*</span></label>
    <input class="ff-c" id="email" name="email" type="email" required>
    <p class="ff-help">We never share it.</p>
    <p class="ff-error" role="alert" hidden></p>
  </div>
  <button class="btn btn-primary" type="submit">Save</button>
</form>
        Validate fields
        <!-- native attributes: required, type=email|url|tel|number, min, max, minlength, maxlength, pattern -->
<input class="ff-c" name="zip" required pattern="[0-9]{5}" data-pattern-message="Use 5 digits.">
<input class="ff-c" name="confirm" data-match="#password">
<input class="ff-c" name="user" data-rule="noSpaces">

<script>
AppForms.rules.noSpaces = value => /\s/.test(value) ? "No spaces allowed." : "";
</script>
        Collect values and handle submission
        const form = document.getElementById("signup");

form.addEventListener("appform:valid", async e => {
  const values = e.detail.values;            // { email: "...", interests: [...], items: [{ label: "..." }] }
  const id = toast.loading("Saving...");
  // send values with fetch / $.ajax (see the Laravel example)
});

form.addEventListener("appform:invalid", e => console.log(e.detail.errors));
        Display errors manually
        AppForms.setErrors(form, { email: ["This email is already taken."] });
AppForms.clearErrors(form);
AppForms.reset(form);
        Laravel validation (422) integration
        fetch("/users", {
  method: "POST",
  headers: { "Accept": "application/json", "X-CSRF-TOKEN": csrfToken, "Content-Type": "application/json" },
  body: JSON.stringify(values)
}).then(async res => {
  if (res.status === 422) {                      // Laravel: { message, errors: { field: ["msg"] } }
    AppForms.setErrors(form, await res.json());  // shows each message under its field
    toast.error("Please fix the highlighted fields.");
  } else if (res.ok) {
    toast.success("Saved.");
  }
});

        Documentation

        API

        CallDescription
        AppForms.validate(form)Runs all rules, shows errors, returns { valid, errors }
        AppForms.values(form)Collects values (arrays for multi-select/tags/checkbox groups, nested objects for a[0][b] names)
        AppForms.setErrors(form, errors)Accepts Laravel { errors: { field: [..] } } or { field: msg }
        AppForms.clearErrors / resetClears messages / resets the form and widgets
        AppForms.rulesRegister custom rules for data-rule
        appform:valid / appform:invalidEvents on form[data-ff-form] submit

        Widget attributes

        data-ff = password, number, multiselect, combobox, tags, otp, file, color, phone, repeater. Widgets that produce arrays write a hidden [data-ff-value] input.

        Theme

        Uses the dashboard tokens (border, radius, accent focus ring, density height). Date picker: the original archive has none, so the native date input is used.
